# Tools Reference

Lookup tables moved out of `CLAUDE.md` on 2026-08-13, verbatim, when that file was 1.38x over
its 40KB always-loaded budget. Nothing here was reworded in the move.

**Read this before invoking any `tools/*.py` script**, before touching `tools/launchd/`, or when
a gitignored private config file appears to be missing.

**What deliberately did NOT move, and still lives in `CLAUDE.md`:** the `PYTHONIOENCODING=utf-8`
requirement on every script, and the prohibition on creating/truncating/`touch`ing files in
`tools/launchd/logs/` from a Claude Code Bash call. Those are prohibitions with destructive
failure modes, not lookups, so they stay in the always-loaded tier even though they sit beside
these tables.

| `mutation_check.py` | Deterministic mutation testing: breaks the code on purpose and reports whether any test dies. Classifies each kill as `assertion` (a test checked a value), `error`/`timeout` (a WEAK kill — observed only by crashing), or `unknown` (unparseable, never counted as weak). Also statically flags assertion-free and tautological tests. `--isolation` runs each test file alone; `--strict` fails on weak kills. **Refuses to mutate itself** and keeps a sidecar backup — it rewrites live source, and on 2026-08-19 a self-run corrupted two bystander files. A MANUAL instrument, NOT a gate. |
| `mutation_sweep.py` | Runs `mutation_check.py` across the whole tool corpus and banks one JSON line per tool. **Serial on purpose** — the engine rewrites its target in place, so two runs in one tree corrupt each other; parallelism means one git worktree per runner, never one tree. **Resumable**: banked tools are skipped, so a kill or reboot costs at most the tool in flight. A timeout or unparseable result is recorded `UNAUDITED_*`, never as zero survivors — an empty scan is not a clean one. `--targets` rebuilds the list and runs no mutations. Selection does NOT consult `mutation-allow.json` (it is per-MUTANT and honoured by `mutation_check.py`); excluding whole tools there had silently removed 9 from the corpus, including the public-repo PII hook. Per-tool cap 120 min, and a timed-out tool is repaired before the next starts — SIGKILL cannot be caught, so one timeout used to leave a mutated file that poisoned 41 later results. Self-excludes (it executes from that file), as does `mutation_check.py`; both are recorded `mutants: -1` so the accounting still names them. **While it runs the tree is unsafe for ordinary work** — one `tools/*.py` is mutated at any instant and skills that shell out would run the mutant against real data. Runbook: `docs/mutation-baseline-runbook.md` |
| `job_quiesce.py` | Unloads every `com.nickmagnuson.jobsearch.*` launchd job for the duration of a mutation sweep and restores exactly the ones that were up. **Not a general-purpose tool — it is the sweep's own restore path**, which is why `mutation_sweep.build_targets` refuses to mutate it (`RUNNER_DEPENDENCIES`): a SIGKILL mid-mutation would leave the NEXT run importing a mutated restorer at startup. The guard cannot live inside the scheduled tools themselves, because mutating a guard's own `if` is what the sweep does. Marker file records what went down BEFORE the first bootout; a failed restore KEEPS the marker so the next sweep or the 08:00 `check_automation_health.py` retries. Restore by hand: `bash tools/launchd/install.sh install`. |
| `mutation_report.py` | Turns a sweep into the ranked worst-first survivor map. **States coverage FIRST and names every unmeasured tool**, so a partial run cannot read as a complete one — the failure it guards is real here, where a scan of 64 of 883 files was once reported as a corpus-wide percentage. Every ratio prints its denominator and how that denominator was obtained. `UNAUDITED_*` rows are excluded from all totals and listed separately. Also reports the crash-only kill share per tool: few survivors plus mostly crash kills is not a well-tested tool, just one that crashes readily. |
| `mutation_trend.py` | The longitudinal record `mutation_report.py` cannot keep, because each sweep overwrites the last. `record` appends one dated row per sweep (survival %, mutants, survivors, clean tools, no-verdict tools); `show` prints the series with deltas. **Append-only, and it refuses to re-record an unchanged baseline** — two `record` calls after one sweep would otherwise invent a second data point showing zero change, which reads as 'we measured again and nothing moved'. Tools with no verdict are excluded from the denominator rather than counted as clean: folding an errored tool in as a zero reports an UNMEASURED tool as a protected one. The number to watch is the survival percentage — 33.88% on 2026-09-02. |
| `blind_canary.py` | Detects whether a supposedly-blind agent read material it was never handed, as a set difference on disk (`outside_only = tokens(engagement dir) - tokens(scratch)`). **Always emits a `control` block**, including when no token was supplied: `checked: false` means blindness is UNPROVEN and a clean result must not be read as a proven one (before 2026-08-19 `--control ""` skipped the check and the key was absent entirely, while a WRONG token correctly refuses). Detects TOKEN leakage, not CONCEPT leakage. Exit 3 = refused. |
| `audit_rule_violations.py` | The back-propagation sweep, prescribed at **CLAUDE.md:86** as a mandatory Self-Improvement-Loop step: `--pattern '<regex>'` finds every existing artifact already violating a newly-learned rule. **Read `files_scanned`, not `files`** — `files` counts files WITH violations and so reads 0 on a genuine clean sweep, which is why a scope-of-nothing used to be indistinguishable from clean. `exts_applied` / `exts_defaulted` state the scope; `--ext ""` normalizes to `{"."}` and scans nothing. Exit 0 always: a report, not a gate. |
| `check_table_integrity.py` | PostToolUse hook (`Bash|Write|Edit|MultiEdit`) + standalone scanner for a markdown-table row whose pipe-delimited field count differs from the rest of its own table — the signature of an unescaped `|` inside a cell, which shifts every later column right by one. **Silent in all four directions that matter:** the file still renders as a table, index-based parsers return a plausible value from the neighbouring cell without raising, name-based parsers silently disagree with them, and nothing downstream flags it. Self-calibrating (modal field count per contiguous run, no per-file column map), so it stays correct when a table gains a column. Fail-open: any unexpected exception exits 0. ~1.2ms per pass. |
| `friction_log.py` | The `--debug` ledger (`append` / `list` / `query` / `resolve`), ladder at CLAUDE.md:33. **`list` output carries `filters_applied` + `total_rows`** — `--surface` is truthiness-tested, so `--surface ""` silently returns the whole ledger where a scoped query returns 1 row, and the ladder counts fires PER SURFACE. `filters_applied.surface` mirrors the filter that actually ran (whitespace included), so the report cannot misstate its own scope. |

## Multi-agent workflows

**Multi-agent workflows.** Reusable orchestration templates live in `.claude/workflows/*.js`, invocable as skills. Patterns documented in `framework/multi-agent-workflows.md`: agents supply judgment, the script supplies deterministic control flow (fan-out, loops, convergence gates).

| Workflow | Pattern | Use when |
|---|---|---|
| `/plan-hardening` | **v2 since 2026-08-21** (`framework/plan-hardening-v2-spec.md`). Two layers: a premise gate that HARD STOPS before any execution critique, then scoped probes with a **per-hole regression retest** ("does hole E4 still fire?"). Returns a residual risk register with a retest verdict per finding — **there is deliberately no `airtight` boolean** — and persists it via `registerPath`/`outPath`. Replaces the round-based panel, which failed to converge in two instrumented runs. Launch with `scriptPath`, never `name` (stale-snapshot bug). | Before executing an expensive or irreversible plan |
| `/extract-verify` | Extract records, then re-derive each in a fresh context (anti-anchoring) | Turning a messy corpus into a labeled dataset with provenance |
| `/research-audit` | Fan-out research per angle + adversarial claim validation | Deciding whether existing systems are stale and what to change |

Args are passed as a **JSON object**, not a bare string — e.g. `{"planPath": "...", "context": "...", "registerPath": "...", "outPath": "..."}`. A bare string fails at parse time before any agent runs. (`maxRounds` and `lenses` appeared in this example until 2026-08-21; **both were deleted in the v2 rewrite and no workflow reads them.**)

Python 3.10+ (several `tools/*.py` use PEP 604 `X | None` annotations evaluated at def time — e.g. `networking_read.py`, `networking_followup.py`, `pipe_read.py`, `pipeline_staleness.py`). `pip install -r requirements.txt` for PDF features. **All `tools/*.py` scripts require `PYTHONIOENCODING=utf-8` prefix or they crash on Unicode.**

**CV PDFs use RenderCV** (`~/.local/bin/rendercv render <yaml>`) — see `/generate-cv` and `/apply` SKILL.md for the full pipeline. Reference YAML: `output/example-ventures/042826-cos-example.yaml`. Theme: `framework/cv-themes/tuck-mbb.yaml`.

**Email drafts.** Use `tools/open_draft.py` (Google MCP lacks draft-creation permissions). Write `tools/.pending-draft.txt`:

```
TO: recipient@example.com
CC: optional@example.com
SUBJECT: Subject line
BODY:
Email body here
```

`CC:` is optional (omit the line entirely if unused). Then `PYTHONIOENCODING=utf-8 python3 tools/open_draft.py` opens Gmail compose pre-filled.

**Post-interview workflow:**
1. `data/company-notes/<slug>.md` — call intel, newest at top
2. `pipe_write.py` — stage, next-action, notes
3. `networking_write.py log` — interaction
4. `todo_write.py add` — follow-up task
5. `tools/open_draft.py` — thank-you email
6. If a mock session preceded the call: update `coaching/progress-recruiter/`

- Filter separator-row noise from script output: `[e for e in entries if e.get("task") != "---"]`.
