# Job Search OS for Claude Code

A system for running a job search inside [Claude Code](https://code.claude.com/docs), Anthropic's command-line tool that lets Claude work directly with files on your computer. It researches companies, tailors CVs, drafts outreach, prepares for interviews, and keeps notes on contacts and decisions.

Built by Nick Magnuson during his 2026 job search, extending [Raphael Otten](https://www.linkedin.com/in/raphaelotten/)'s open-source AI interview-coaching toolkit into a full search workflow. A job search runs for months and builds up context: companies, people, decisions, and how you write. A chat with an AI assistant usually starts from a blank page. This one keeps that context in plain text files and reads it before it writes.

Commands are written in plain English (markdown files) that Claude follows, so using it means typing commands in Claude Code. Setup needs a terminal, Python, and git, but no programming. The files also open as an [Obsidian](https://obsidian.md) vault, which is optional.

**Start here:** [why it exists](docs/why.md) · [run the demo](docs/getting-started.md) · [end-to-end workflows](docs/workflows.md)

## What it does that a folder of prompts does not

**It remembers.** Profile, goals, pipeline, contacts, and past decisions live in markdown files under `data/`. The research, writing, and interview-prep commands read them before they write, so the tool does not start from a blank prompt each session. A dossier written before a first call is still there in the third round.

**Email drafts flag anything Claude made up about the user.** Each draft from the email skills labels every substantive sentence by where it came from:

- **N**: the user's own words from this session (typed or dictated)
- **C**: the user's earlier writing (prior sent email)
- **I**: inferred by Claude from cited research
- **G**: generated by Claude with no source

A **G** sentence about who the user is, what they bring, or what they have done stops the draft until the user supplies their own words. The check runs inside the drafting skills. An email typed directly in chat skips it, which is why outbound email should be drafted with `/draft-email`, `/cold-outreach`, `/follow-up`, or `/outreach-batch`.

**Its most important rules are checked by code.** Hooks are small Python scripts wired to specific file reads, writes, and commands. When Claude makes one of those calls, the hook can block a known mistake before it happens. Examples: a real contact's name being written into this public repo, an email draft that pairs "Monday" with a date that falls on a Tuesday, or a reply claiming a file was saved when no write happened.

## An example: first contact with someone at a target company

1. `/research-company "Acme Corp"` (fictional company) writes a sourced dossier to `output/acme-corp/acme-corp.md`.
2. `/cold-outreach "Jamie Torres" "Acme Corp"` (fictional contact) reads that dossier, the user's profile, and any prior notes on the contact, then writes an Outreach Brief: why now, facts about the recipient with a source for each, which of the user's experiences are relevant, and what not to say.
3. The skill stops. The user states the main point of the message in their own words.
4. Claude drafts from that point, labels each sentence by source, and hooks check the draft for known style problems (em dashes, filler phrases) before a Gmail compose window opens with the draft. Nothing is sent automatically.
5. After the user approves, the message is saved to the user's private notes (`data/networking.md`), and a follow-up to-do is created.

A sample CV generated from the fictional demo profile: [`sample-cv-priya-anand.pdf`](examples/output/sample-cv-priya-anand.pdf).

## Lessons from building it

**Measure what gets used.** An April-May 2026 review of how often each command ran showed that a handful carried most of the daily work: `/wispr` (pulls in notes dictated with the Wispr Flow app), `/remember` (route a note to the right file), `/draft-email`, `/standup` (morning briefing), and `/checkout` (end-of-day close-out). Several commands that made sense on paper were rarely used, such as `/act` (an autonomous task runner) and `/dashboard` (a terminal dashboard). They are kept for occasional use.

**Instructions are not enough; checks are.** Rules written only as instructions to Claude were skipped in long or busy sessions. Rules written as hooks that block the tool call hold on every call they cover. Recurring failures are logged to a friction ledger, and a failure that keeps recurring is turned into a hook. The full list of hooks and what each one blocks is in [docs/hooks.md](docs/hooks.md).

## How it is built

| Layer | Where | What it holds |
|---|---|---|
| Data | `data/` (private, kept out of this public repo) | The user's profile, goals, pipeline, contacts, decisions, and per-project records that CVs are built from |
| Skills | [`.claude/skills/`](.claude/skills/) | 40 slash commands, each a markdown file listing its steps and, for most, which data files it reads |
| Hooks | `tools/check_*.py`, wired in [`.claude/settings.json`](.claude/settings.json) | Checks that run on tool calls and block known failures ([full list](docs/hooks.md)) |
| Framework | [`framework/`](framework/) | Methodology the skills follow: the CV workflow and 20-point checklist, interview coaching protocol, recruiter-call answering strategies, style guide |

Skills reference framework docs by path, so a rule changed in one framework file applies to every skill that uses it. Supporting Python scripts in `tools/` handle file writes that must be atomic, PDF rendering, and scheduled background jobs. A pytest suite in `tests/` covers the tools and hooks.

## Privacy: the system is public, the data is not

The user's data is gitignored, so git leaves it out of this public repo: `data/`, `output/`, `coaching/`, and `memory/`. An end-of-day step in `/checkout` commits that data to a separate private repository instead, so the search history is still versioned.

The public repo also has leak checks. A hook (`tools/check_public_pii.py`) blocks Claude from writing names on a private denylist (known contacts and target companies) into any tracked file. It does not check commits made by hand. The `/audit-pii` skill, run before a commit, checks more broadly for names the list does not cover. Details: [docs/privacy.md](docs/privacy.md).

## Getting started

For a full walkthrough with the demo profile, see [docs/getting-started.md](docs/getting-started.md). The short version:

**Prerequisites:** [Claude Code](https://code.claude.com/docs) (Anthropic's paid Max plan is recommended, since the research and CV review skills run many parallel requests) and Python 3.10+.

**1. Clone and install**

```bash
git clone https://github.com/nickmagnuson2-jpg/claude-job-search-os.git
cd claude-job-search-os
python3 -m pip install -r requirements.txt  # pyyaml is required; the rest are optional (PDF, Gmail, dashboard)
```

Open the folder in Claude Code.

**2. Try the demo profile (optional)**

```bash
mkdir -p data output
cp -r examples/data/. data/
cp -r examples/output/. output/
```

**3. Import your own data**

If you tried the demo, delete the demo files from `data/` and `output/` first, or `/import-cv` adds your history to the fictional profile.

```
/import-cv path/to/your-cv.pdf
/extract-identity
/setup-goals
```

`/import-cv` extracts your history into `data/` and can be run again with other CVs to add more. `/extract-identity` is a guided conversation that writes `data/professional-identity.md`. `/setup-goals` writes `data/goals.md`. The generative skills check that `data/profile.md` and `data/goals.md` exist and stop with instructions if either is missing.

**4. Use it**

```
/standup                          # morning briefing
/research-company "Acme Corp"     # company dossier before a call
/draft-email "Jamie Torres" "thank you for coffee chat"
```

## Repository layout

```
CLAUDE.md          Project instructions, loaded every Claude Code session
.claude/skills/    The 40 skill definitions
framework/         Methodology docs and templates
tools/             Python scripts and hooks
tests/             pytest suite for the tools and hooks
```
